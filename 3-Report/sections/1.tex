\section{Verification of reactivity properties}
\subsection{Problem overview}
The goal is to develop an algorithm that can verify a specific class of LTL
properties called reactivity properties. These are formulas of the form
\[\always\eventually f \implies \always\eventually g\] where \(f\) and \(g\)
are Boolean formulas without temporal operators.\\[2ex]
The formula asserts that if the condition \(f\) keeps becoming true infinitely
often, then the condition \(g\) must also occur infinitely often. The solution
presented checks whether its negation holds rather than directly proving the
implication.\\[2ex]
The negation of the formula \(\always\eventually f \implies \always\eventually
g\) is \(\always\eventually f \implies \always\eventually \neg g\). Intuitively
the orignal formula is violated if there is an execution in which \(f\) continues
to occur infinitely often while \(g\) permanently stops occurring. \\[2ex]
The core function delivered searches for a cycle in the state space where
\(f\) is satisfied and \(g\) is not. Finding such a cycle is sufficient to prove
the property is not valid, and was partially covered during lectures. In short,
if the formula \(\always\eventually f \AND \lnot g\) is satisfiable, the witness
is build identifing the loop head, then constructing the loop body, builds the
prefix that leads to it from the initial states, and finally combining
everything into a concrete trace. This trace acts as a counterexample to the
original property.

\subsubsection{Sanity check and model preparation}
\begin{small}
    \begin{verbatim}
        
    parse_result = parse_react(spec)
    if parse_result is None:
        return None

    f, g = parse_result
    ng = pynusmv.prop.not_(g)

    fsm_bdd = pynusmv.glob.prop_database().master.bddFsm

\end{small}
The implementation begins by parsing the input specification to ensure it
matches the required reactivity property form. If the formula does not
conform, the function exits early. Otherwise, the Boolean formulas
\(f\) and \(g\) are extracted, and the negation of \(g\) is constructed.
The finite state machine is then prepared in BDD form, and both \(f\) and
\(\neg g\) are converted into their corresponding BDD representations.
This setup enables efficient symbolic manipulation in the subsequent
verification steps.

\subsubsection{Symbolic repeatability check}
\begin{small}
    \begin{verbatim}

    recur_bdd = reach_bdd.intersection(f_bdd).intersection(ng_bdd)
    while fsm_bdd.count_states(recur_bdd) > 0:
        pre_reach_bdd = new_bdd = fsm_bdd.pre(recur_bdd).intersection(ng_bdd)
        while fsm_bdd.count_states(new_bdd) > 0:
            pre_reach_bdd = pre_reach_bdd.union(new_bdd)
            if recur_bdd.entailed(pre_reach_bdd):
                # Here property is repeatable
                # witness construction
                return (False, witness)
            new_bdd = (fsm_bdd.pre(new_bdd).diff(pre_reach_bdd)).intersection(ng_bdd)
        recur_bdd = recur_bdd.intersection(pre_reach_bdd)
    # Here property is not repeatable
    return (True, None)

\end{verbatim}
\end{small}
The repeatability check is implemented as described in the course
(see \hyperref[fig:repeatability-algorithm]{Figure 2}), with some
structural differences:
\begin{itemize}
    \item \texttt{recur\_bdd} is defined as the intersection of the
          reachable states, \texttt{f\_bdd}, and \texttt{ng\_bdd},
          following the outlined strategy.
    \item \texttt{pre\_reach\_bdd} is reset to \texttt{new\_bdd} instead
          of the empty set to simplify the implementation. This doesn't affect
          the correctness of the algorithm since, for each states of \texttt{recur\_bdd}
          the first initialization of \texttt{pre\_reach\_bdd} is the only difference 
          from the original, and \(\emptyset \ \cup\) \texttt{new\_bdd} is equivalent to 
          \texttt{new\_bdd} \(\cup\) \texttt{new\_bdd}.
\end{itemize}

\subsubsection{Witness construction}
As anticipated above the witness is contructed when \(\always \eventually f 
\AND \neg g \) is repeatable, that is when the entire recurrent region can 
be regenerated through repeated application of the pre-image operator under 
the constraint \(\neg g\), that is a complex way of saying when
\begin{enumerate}
    \item Beginning from the set of reachable states that satisfy 
        \( f \land \neg g \) (\texttt{recur\_bdd}),
    \item Iteratively find states that can reach \texttt{recur\_bdd} without leaving 
        \( \neg g \) \\(\texttt{pre\_reach\_bdd}),
    \item In one iteration all \texttt{recur\_bdd} is included in 
        \texttt{pre\_reach\_bdd} so it's possible to go backward 
        from every recurrent state to some other state also within the 
        same set without leaving \( \neg g \).
\end{enumerate}
The solution implements the witness construction algorithm
as described in the course, with some minor modifications to adapt it to the
symbolic framework and an additional phase not treated of trace composition.

\paragraph{Loop head identification}
\begin{small}
\begin{verbatim}
    recur_states_list = list(fsm_bdd.pick_all_states(recur_bdd))
    loop_head = recur_states_list.pop(0)
    while True:
        R = None
        Frontiers = []
        new_bdd = fsm_bdd.post(loop_head).intersection(pre_reach_bdd)
        while fsm_bdd.count_states(new_bdd) > 0:
            R = new_bdd if R is None else R.union(new_bdd)
            Frontiers.append(R)
            new_bdd = fsm_bdd.post(new_bdd).intersection(pre_reach_bdd)
            new_bdd = new_bdd.diff(R)
        R = R.intersection(recur_bdd)
        if loop_head.entailed(R):
            break
        else:
            loop_head = recur_states_list.pop(0)

\end{verbatim}
\end{small}

\paragraph{Loop body construction}
\begin{small}

    k = 0

\paragraph{Connecting loop and initial states}
\begin{small}
\begin{verbatim}

    images = list()
    counterex = pre_counterex = loop_head
    images.append(counterex)
    while not pre_counterex.intersected(fsm_bdd.init):
        counterex = pre_counterex
        pre_counterex = fsm_bdd.pre(counterex)
        images.insert(0, pre_counterex)

\end{verbatim}
\end{small}

\paragraph{Trace construction}
\begin{small}
\begin{verbatim}

    trace_init = list()
    start = fsm_bdd.init  # Start from initial states
    for i in range(0, len(images) - 1):
        start = start.intersection(images[i])
        post = fsm_bdd.post(start).intersection(images[i + 1])
        trace_init.append(fsm_bdd.pick_one_state(start).get_str_values())
        trace_init.append(
            fsm_bdd.pick_one_inputs(
                fsm_bdd.get_inputs_between_states(start, post)
            ).get_str_values()
        )
        start = post
    witness = trace_init + trace

\end{verbatim}
\end{small}

The witness construction is performed as described in the course, with the
following steps:
\begin{itemize}
    \item The loop head is identified as the first state in \texttt{recur\_bdd}.
    \item The loop body is constructed by iteratively applying the pre operator
          to the loop head until no new states are found.
    \item The prefix leading to the loop head is built by applying the post operator
          to the initial states until the loop head is reached.
    \item Finally, the trace is constructed by combining the prefix and the loop body.
    \item The trace is returned as a counterexample to the original property.
    \item If the property is repeatable, the function returns \texttt{False} and the
          witness trace; otherwise, it returns \texttt{True} and \texttt{None}.
\end{itemize}
