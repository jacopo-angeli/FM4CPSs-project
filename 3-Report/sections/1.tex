\section*{Verification of reactivity properties}
\subsection*{Problem overview}
The goal is to develop an algorithm that can verify a specific class of LTL properties called reactivity properties. These are formulas of the form \[\always\eventually f \implies \always\eventually g\] where \(f\) and \(g\) are Boolean formulas without temporal operators.\\[2ex]
The formula asserts that if the condition \(f\) keeps becoming true infinitely often, then the condition \(g\) must also occur infinitely often. The solution presented checks whether its negation holds rather than directly proving the implication.\\[2ex]
The negation of the formula \(\always\eventually f \implies \always\eventually g\) is \(\always\eventually f \AND \always\eventually \neg g\) that follows from the logical equivalence \(f \rightarrow g \equiv \neg f \lor g\), hence \(\neg (f \rightarrow g) \equiv f \land \neg g\). Intuitively the orignal formula is violated if there is an execution in which \(f\) continues to occur infinitely often while \(g\) permanently stops occurring. Instead of proving the implication directly, the algorithm searches for a counterexample to the implication by checking the negation, \\[2ex]
The solution searches for a cycle in the state space where \(f\) is satisfied and \(g\) is not. Finding such cycle is sufficient to prove the property is not valid, and was partially covered during lectures. In short, if the formula \(\always\eventually f \AND \lnot g\) is satisfiable, the witness is build identifying the loop head, then constructing the loop body, builds the prefix that leads to it from the initial states, and finally combining everything into a concrete trace. This trace acts as a  counterexample to the original property.

In case of a valid reactivity formula \(f\) and \(g\) are extracted, and the negation of \(g\) is constructed. The finite state machine is then prepared in BDD form, and both \(f\) and \(\neg g\) are converted into their corresponding BDD representations.

\subsubsection*{Reachable states}
The usage of \texttt{reachable\_states} from the \texttt{pynusmv} library wasn't allowed for this project, hence the solution implements verbatim the symbolic BFS algorithm presented in Part 7 of the course. The algorithm explores the state space starting from the initial region, by definition reachable and incrementally expanding the set of reachable states by computing successors and discarding already visited states until no new states are found.
\begin{scriptsize}
\begin{verbatim}
        
    reach_bdd = fsm_bdd.init
    new_bdd = fsm_bdd.post(reach_bdd)
    while fsm_bdd.count_states(new_bdd) > 0:
        new_bdd = fsm_bdd.post(new_bdd).diff(reach_bdd)
        reach_bdd = reach_bdd.union(new_bdd)

\end{verbatim}
\end{scriptsize}

\subsubsection*{Symbolic repeatability check}
The repeatability check essentially computes a fixed point over the reachable state space considering only the transitions that satisfy the input formula, returning a set that remains unchanged under repeated application of the pre-image operator. In each iteration it identifies the set of states that can reach the previous set in a single step, (i.e.\ their pre-image) starting from the portion of initial states that satisfies \(f \AND \neg g\).\\[2ex]
If the set of states stabilizes, meaning it does not change after applying the pre-image operator, then the property is repeatable and the algorithm returns \texttt{(True, None)}. If instead the set keeps changing, it means that there exists a loop in which \(f\) is satisfied and \(g\) is not, hence the property is not repeatable and a witness can be constructed. The witness construction is treated in the next subsection, hence the following code is the main body of the repeatability check where the witness contruction starting point is indicated by a comment:
% chktex 36 off
\begin{scriptsize}
\begin{Verbatim}[commandchars=\\\{\}]

    \textcolor{BrickRed}{recur_bdd = reach_bdd.intersection(f_bdd).intersection(ng_bdd)}
    while fsm_bdd.count_states(recur_bdd) > 0:
        \textcolor{BrickRed}{pre_reach_bdd = new_bdd = fsm_bdd.pre(recur_bdd).intersection(ng_bdd)}
        while fsm_bdd.count_states(new_bdd) > 0:
            pre_reach_bdd = pre_reach_bdd.union(new_bdd)
            if recur_bdd.entailed(pre_reach_bdd):
                \textcolor{Gray}{# witness construction}
                return (False, witness)
            \textcolor{BrickRed}{new_bdd = (fsm_bdd.pre(new_bdd).diff(pre_reach_bdd)).intersection(ng_bdd)}
        recur_bdd = recur_bdd.intersection(pre_reach_bdd)
    return (True, None)

\end{Verbatim}
\end{scriptsize}
% chktex 36 on

About \texttt{recur\_bdd} and \texttt{new\_bdd} initialization, the algorithm focuses on the subset of reachable states satisfying \(f \land \neg g\), hence the intersection with \texttt{ng\_bdd}. urthermore, \texttt{pre\_reach\_bdd} is initialized to \texttt{new\_bdd} as a simplification of the algorithm without affecting its correctness. The first iteration of the while loop will always include \texttt{new\_bdd} in \texttt{pre\_reach\_bdd} anyway, and \(\emptyset \cup \texttt{new\_bdd} = \texttt{new\_bdd}\).

\subsubsection*{Witness construction}
The precondition to enter this portion of the code is that \(f \AND \neg g\) is repeatable. The first step to produce the witness at this point is to identify a loop head from the recurrent set computed above. At this stage in fact, \texttt{recur\_bdd} contains all the states that can be reached infinitely often. Among these, there exists at least one state that can reach \textit{itself} infinitely often, thus forming a loop.\\[2ex]
To find such a state, the algorithm iteratively tests each state in \texttt{recur\_bdd}. Starting from a candidate state, it repeatedly applies the post operator (restricted to \texttt{pre\_reach\_bdd}) to explore its successors (i.e., the set of states that can reach the portion of reachable states satisfying \(f \AND \neg g\)) until no new states are found. If at any iteration the candidate state is included in the set of visited states, then it is selected as the loop head; otherwise, the algorithm proceeds to the next candidate in \texttt{recur\_bdd}.
\begin{scriptsize}
\begin{Verbatim}[commandchars=\\\{\}]

    loop_head = recur_states_list.pop(0)
    while True:
        \textcolor{BrickRed}{Frontiers = []}
        new_bdd = fsm_bdd.post(loop_head).intersection(pre_reach_bdd)
        \textcolor{BrickRed}{R = new_bdd}
        while fsm_bdd.count_states(new_bdd) > 0:
            R = R.union(new_bdd)
            \textcolor{BrickRed}{Frontiers.append(R)}
            new_bdd = fsm_bdd.post(new_bdd).intersection(pre_reach_bdd)
            new_bdd = new_bdd.diff(R)
        R = R.intersection(recur_bdd)
        if loop_head.entailed(R):
            break
        else:
            loop_head = recur_states_list.pop(0)

\end{Verbatim}
\end{scriptsize}
The solution is a direct translation of the pseudo-code presented during the course, modified as instructed to keep track of the sequence of frontiers useful to later reconstruct the loop body. \texttt{Frontiers} is initialized as empty and populated iteratively with layers. \texttt{Frontiers[i]} contains all the states that can be reached from the loop head in exactly \(i\) steps. The initialization of \texttt{R} to \texttt{new\_bdd} is instead a pure simplification of the algorithm due to similar easoning to the one used in the repeatability check, since the first iteration of the while loop will always include \texttt{new\_bdd} in \texttt{R} anyway, and \(\emptyset \cup \texttt{new\_bdd} = \texttt{new\_bdd}\).\\[2ex]
Once the loop head has been identified, the algorithm proceeds to reconstruct the loop body. The goal is to extract one specific trace through the system that starts at some earlier state, progresses step by step, and eventually returns to the loop head, thereby forming a cycle.\\[2ex]
The algorithm first identifies the smallest index \(k\) such that the loop head appears in \texttt{Frontiers[k]}, meaning there is a path of length \(k\) from the loop head back to itself. This defines the loop length (\texttt{k}). Starting from the loop head, the algorithm then reconstructs the loop by moving backward layer by layer, selecting at each step a predecessor of the current state that is in the correct frontier layer, while building the trace for visualization and the loop body. Below the python code that is strangely naturally divided by the end of the page:
\begin{scriptsize}
\begin{Verbatim}[commandchars=\\\{\}]

    k = 0
    while not loop_head.entailed(Frontiers[k]):
        k += 1
    

    loop = [loop_head]
    curr = loop_head
    {\color{BrickRed}trace = [loop_head.get_str_values()]}
    for i in range(k - 1, -1, -1):
        Pred = fsm_bdd.pre(curr).intersection(Frontiers[i])
        curr = fsm_bdd.pick_one_state(Pred)
        loop = [curr] + loop
        {\color{BrickRed}trace = [}
            {\color{BrickRed}curr.get_str_values(),}

                {\color{BrickRed}fsm_bdd.get_inputs_between_states(curr, loop[0])}
            {\color{BrickRed}).get_str_values(),}
        {\color{BrickRed}] + trace}

    loop = [loop_head] + loop
    {\color{BrickRed}trace = [}
        {\color{BrickRed}loop_head.get_str_values()},
        {\color{BrickRed}fsm_bdd.pick_one_inputs(}
            {\color{BrickRed}fsm_bdd.get_inputs_between_states(loop_head, loop[0])}

\end{Verbatim}
\end{scriptsize}
The code above is actually a direct translation of the pseudo-code presented during the course, with the addition of the \texttt{trace} variable to store the concrete trace for visualization purposes. The trace is built by concatenating the string representation of the current state and the input that leads to the next state, ensuring that the trace reflects the actual transitions taken in the system.\\[2ex] 
The final step in constructing the counterexample witness involves generating a concrete path from an initial state to the previously identified loop head. The solution implements two sequential traversals:
\begin{itemize}
    \item a backward search begins from the loop head and repeatedly applies the pre-image operator 
          to symbolically compute the set of states that can reach the current set in one transition.
          This process continues until a state intersecting with the set of initial states is found, 
          and the sequence of sets (stored in \texttt{images}) effectively encodes a path backward 
          from the loop to the initial state space,
    \item To obtain a concrete, step-by-step trace, the forward traversal is applied to the computed 
          \texttt{images}: at each layer, the intersection with the current reachable states and the 
          post-image is used to extract one possible transition. A concrete state and the corresponding 
          input leading to the next state are then appended to \texttt{trace\_init}, reconstructing the 
          prefix of the counterexample.
\end{itemize}
Finally, the prefix (\texttt{trace\_init}) and the loop body (\texttt{trace}) are concatenated into a single sequence (\texttt{witness}). 
\begin{scriptsize}
\begin{Verbatim}[commandchars=\\\{\}]

    {\color{BrickRed}images = list()}
    {\color{BrickRed}counterex = pre_counterex = loop_head}
    {\color{BrickRed}images.append(counterex)}
    {\color{BrickRed}while not pre_counterex.intersected(fsm_bdd.init):}
        {\color{BrickRed}counterex = pre_counterex}
        {\color{BrickRed}pre_counterex = fsm_bdd.pre(counterex)}
        {\color{BrickRed}images.insert(0, pre_counterex)}

    {\color{BrickRed}trace_init = list()}
    {\color{BrickRed}start = fsm_bdd.init}
    {\color{BrickRed}for i in range(0, len(images) - 1):}
        {\color{BrickRed}start = start.intersection(images[i])}
        {\color{BrickRed}post = fsm_bdd.post(start).intersection(images[i + 1])}
        {\color{BrickRed}trace_init.append(fsm_bdd.pick_one_state(start).get_str_values())}
        {\color{BrickRed}trace_init.append(}
            {\color{BrickRed}fsm_bdd.pick_one_inputs(}
                {\color{BrickRed}fsm_bdd.get_inputs_between_states(start, post)}
            {\color{BrickRed}).get_str_values()}
        {\color{BrickRed})}
        {\color{BrickRed}start = post}
    {\color{BrickRed}witness = trace_init + trace}

\end{Verbatim}
\end{scriptsize}
The backward-search and forward-extraction together outputs a prefix from an initial state to the loop head, by construction the result of the former is a sequence of BDDs
\begin{center}
\texttt{images[0],…,images[n]}
\end{center}
such that
\begin{center}
\texttt{images[0] }\(\cap\)\texttt{ Init }\(\setminus \ \emptyset\)\texttt{, images[n] = {loop\_head}}
\end{center}
and for each \(0 \le\) \texttt{i} \(< n\), every state in \texttt{images[i]} has at 
least one successor in 
\texttt{images[i+1]}.\\[2ex]
The forward-extraction of the prefix is driven by the list \texttt{images} built during the backward search. The starting point is initialized to the initial states, and then loop from 0 to \texttt{len(image)-1} performing the following steps:
\begin{enumerate}
  \item Restrict the current reachable set to the \texttt{i}th layer:
        \scriptsize
        \begin{verbatim}
    start = start.intersection(images[i])
        \end{verbatim}
  \item Compute the next-layer post-image:
        \scriptsize
        \begin{verbatim}
    post = fsm_bdd.post(start).intersection(images[i+1])
        \end{verbatim}
  \item Extract and appending their string representations to \texttt{trace\_init} one 
        concrete state and the input leading it to the next layer:
        \scriptsize
        \begin{verbatim}
    trace_init.append(fsm_bdd.pick_one_state(start).get_str_values())
    trace_init.append(fsm_bdd.pick_one_inputs(
        fsm_bdd.get_inputs_between_states(start, post)
    ).get_str_values())
        \end{verbatim}
  \item Update \texttt{start} as the post variable in preparation for the next iteration:
        \scriptsize
        \begin{verbatim}
    start = post
        \end{verbatim}
\end{enumerate}
At the end of the loop \texttt{trace\_init} contains a concrete sequence  
\[
[s_0, a_0, s_1, a_1, \dots, s_{n-1}, a_{n-1}, s_n]
\]
where \(s_0\in\texttt{images[0]}\cap\texttt{fsm\_bdd.init}\) and \(s_n=\texttt{loop\_head}\), hence a looping execution in a form of a tuple of alternating states and inputs, starting and ending with a state, where the last state is in the sequence and indicate the starting point of the loop.\\[2ex]  
Finally \texttt{witness = trace\_init + trace} concatenates the prefix with the loop body. At this point, \texttt{witness} contains a concrete counterexample trace that demonstrates the violation of the reactivity property. At this point the symbolic reactivity check function ends and returns \texttt{(False, witness)}.
