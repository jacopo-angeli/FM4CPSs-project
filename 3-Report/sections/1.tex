\section{Verification of reactivity properties}
\subsection{Problem overview}
The goal is to develop an algorithm that can verify a specific class of LTL
properties called reactivity properties. These are formulas of the form
\[\always\eventually f \implies \always\eventually g\] where \(f\) and \(g\) are Boolean formulas without temporal operators.\\[2ex]
By applying logical transformations, the negation of \(\always\eventually f
\implies \always\eventually g\) becomes \(\always\eventually f \and
\lnot\always\eventually g\). The second part, \(\lnot\always\eventually g\), is
equivalent to \(\eventually\always \lnot g\), so the overall formula becomes
\(\always\eventually f \and \eventually\always \lnot g\). This means we are
looking for executions where \(f\) keeps happening infinitely often, but after
some point, \(g\) stops happening altogether.\\[2ex]
To verify this, the algorithm tries to find a cycle (i.e., a looping execution
trace) in the state space where \(f\) is satisfied and \(g\) is not. If such a
cycle exists, it means there is an infinite execution where \(f\) keeps being
true, and \(g\) never becomes true again, i.e.\ exactly what violates the original
property. Since the model checker works with finite representations of infinite
executions using loops, finding such a cycle is sufficient to prove the
property is not valid.\\[2ex]
The solution follows the algorithm with witness output discussed during the
course. If the formula \(\always\eventually f \and \lnot g\)
is satisfiable, the witness is built step by step: the algorithm looks for a
loop head, then constructs the loop body, builds the prefix that leads to it,
and finally puts everything together into a looping trace. This trace acts as a
concrete counterexample to the original property.

wasn't allowed for this project, the solution implemented the symbolic BFS
algorithm presented in Part 7 of the course and shown in \hyperref[fig:one]{Figure 1}. The algorithm

expands the set of reachable states by computing successors and discarding
already visited states.\\[2ex]
The solution follows the same structure, using BDD operations provided by
\texttt{pynusmv} and is the following:
\begin{verbatim}
    reach_bdd = fsm_bdd.init
    new_bdd = fsm_bdd.post(reach_bdd)
    while not new_bdd.equal(reach_bdd.intersection(new_bdd)):
        reach_bdd = reach_bdd.union(new_bdd.diff(reach_bdd))
        new_bdd = fsm_bdd.post(reach_bdd)
\end{verbatim}

\subsection{Implementation details}
\begin{figure}[h]\label{fig:two}
    \centering
    \includegraphics[width=10cm]{../media/symbolic-repeatability-algorithm.png}
    \caption{Symbolic repeatability algorithm presented in class.}
\end{figure}
The implementation of the verification procedure is structured around a single
main function that performs both parsing and symbolic checking of the
reactivity property. The function starts by parsing the input specification to
ensure it has the correct reactivity form \(\always\eventually f \implies
\always\eventually g\). If the formula doesn't match this structure, the
function returns \texttt{None}.

Once the specification is parsed, the body of the algorithm builds BDDs for
both \(f\) and \(\neg g\). These are the core formulas for the negated property
\(\always\eventually f \and \eventually\always \neg g\), which we aim to
verify.

The first computational phase is the symbolic reachability check, implemented
manually using the algorithm from the course, since the use of
\texttt{reachable\_states} from \texttt{pynusmv} was not allowed. This step
computes all states reachable from the initial condition by iteratively
applying the transition relation and accumulating new states until a fixpoint
is reached.

After that, the symbolic repeatability check begins. This phase looks for a
region of the reachable state space where both \(f\) and \(\neg g\) hold, and
attempts to grow this region backwards using pre-image computation. If this
fixpoint expansion includes the entire recurrent region, the property is
considered repeatable, and a counterexample must be built.

If repeatability is confirmed, the algorithm proceeds through three structured
phases of trace construction: (i) a loop is extracted by locating a cycle
within the recurrent region, (ii) the loop body is traced backward from the
loop head, and (iii) a prefix from the initial states to the loop is built. The
final trace is constructed by combining the prefix and the loop into a single
execution trace, alternating states and inputs.

If no such repeatable region exists, the formula is considered satisfied and
the function returns \texttt{(True, None)}. Otherwise, the constructed trace is
returned as a witness for the violation of the property.
