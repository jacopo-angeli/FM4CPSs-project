\section{Verification of reactivity properties}
\subsection{Problem overview}
The goal is to develop an algorithm that can verify a specific class of LTL
properties called reactivity properties. These are formulas of the form
\[\always\eventually f \implies \always\eventually g\] where \(f\) and \(g\)
are Boolean formulas without temporal operators.\\[2ex]
The formula asserts that if the condition \(f\) keeps becoming true infinitely
often, then the condition \(g\) must also occur infinitely often. The solution
presented checks whether its negation holds rather than directly proving the
implication.\\[2ex]
The negation of the formula \(\always\eventually f \implies \always\eventually
g\) is \(\always\eventually f \AND \always\eventually \neg g\). Intuitively
the orignal formula is violated if there is an execution in which \(f\) continues
to occur infinitely often while \(g\) permanently stops occurring. Instead of 
proving the implication directly, the algorithm searches for a counterexample 
to the implication by checking the negation, \\[2ex]
The solution searches for a cycle in the state space where \(f\) is satisfied 
and \(g\) is not. Finding such cycle is sufficient to prove
the property is not valid, and was partially covered during lectures. In short,
if the formula \(\always\eventually f \AND \lnot g\) is satisfiable, the witness
is build identifing the loop head, then constructing the loop body, builds the
prefix that leads to it from the initial states, and finally combining
everything into a concrete trace. This trace acts as a counterexample to the
original property.

The implementation begins by parsing the input specification to ensure it
matches the required reactivity property form. If the formula does not
conform, the function exits early. Otherwise, the Boolean formulas
\(f\) and \(g\) are extracted, and the negation of \(g\) is constructed.
The finite state machine is then prepared in BDD form, and both \(f\) and
\(\neg g\) are converted into their corresponding BDD representations.
This setup enables efficient symbolic manipulation in the subsequent
verification steps.

\paragraph{Symbolic repeatability check}
\begin{scriptsize}
\begin{verbatim}

    recur_bdd = reach_bdd.intersection(f_bdd).intersection(ng_bdd)
    while fsm_bdd.count_states(recur_bdd) > 0:
        pre_reach_bdd = new_bdd = fsm_bdd.pre(recur_bdd).intersection(ng_bdd)
        while fsm_bdd.count_states(new_bdd) > 0:
            pre_reach_bdd = pre_reach_bdd.union(new_bdd)
            if recur_bdd.entailed(pre_reach_bdd):
                # Here property is repeatable
                # witness construction
                return (False, witness)
            new_bdd = (fsm_bdd.pre(new_bdd).diff(pre_reach_bdd)).intersection(ng_bdd)
        recur_bdd = recur_bdd.intersection(pre_reach_bdd)
    # Here property is not repeatable
    return (True, None)

\end{verbatim}
\end{scriptsize}
The repeatability check is implemented as described during part 7 of the 
course. The repeatability check essentially computes a fixed point over the reachable 
state space considering only the transitions that satisfy the formula.\\[2ex]
This fixed point is computed by repeatedly applying the pre-image operator. Each iteration 
identifies the set of states that can reach the previous set in a single step, i.e., 
their pre-image. If the sequence stabilizes, it indicates a set of states that can 
reach each other infinitely often, thereby confirming the presence of a potential cycle.
\begin{itemize}
    \item \texttt{recur\_bdd} is defined as the intersection of the
          reachable states, \texttt{f\_bdd}, and \texttt{ng\_bdd},
          following the outlined strategy.
    \item \texttt{pre\_reach\_bdd} is reset to \texttt{new\_bdd} instead
          of the empty set to simplify the implementation. This doesn't affect
          the correctness of the algorithm since, for each state of \texttt{recur\_bdd}
          the first initialization of \texttt{pre\_reach\_bdd} is the only difference 
          from the original, and \(\emptyset \ \cup\) \texttt{new\_bdd} is equivalent to 
          \texttt{new\_bdd} \(\cup\) \texttt{new\_bdd}.
\end{itemize}

\paragraph{Witness construction}\hfill\\
As anticipated above the witness is contructed when \(\always \eventually f 
\AND \neg g \) is repeatable, that is when beginning from the set of reachable states 
that satisfy \( f \land \neg g \) (\texttt{recur\_bdd}) and iteratively find states that 
can reach \texttt{recur\_bdd} without leaving \( \neg g \) \\(\texttt{pre\_reach\_bdd}),
in the current iteration all \texttt{recur\_bdd} is included in \texttt{pre\_reach\_bdd} 
so it's possible to go backward from every recurrent state to some other state also within the 
same set without leaving \( \neg g \).\\[2ex]
The solution implements the witness construction algorithm
as described in the course, with some minor modifications to adapt it to the
symbolic framework, and includes an additional phase for trace composition that was not 
covered in class. Each phase of the construction is explained in detail below.
\newpage
\noindent The first step is to identify a loop head from the recurrent set computed above,
the algorithm implemented was presented during the lectures, but the underlying idea is the 
following: at this stage, \texttt{recur\_bdd} contains all the states that can be reached 
infinitely often. Among these, there exists at least one state that can reach itself 
infinitely often, thus forming a loop.\\[2ex]
To find such a state, the algorithm iteratively tests each state in \texttt{recur\_bdd}. 
Starting from a candidate state, it repeatedly applies the post operator (restricted to 
\texttt{pre\_reach\_bdd}) to explore its successors (i.e., the set of states that can reach 
the portion of reachable states satisfying \(f \AND \neg g\)) until no new states are found. 
If the candidate state is included in the set of visited states, then it is selected as 
the loop head; otherwise, the algorithm proceeds to the next candidate in \texttt{recur\_bdd}.
\begin{scriptsize}
\begin{verbatim}

    recur_states_list = list(fsm_bdd.pick_all_states(recur_bdd))
    loop_head = recur_states_list.pop(0)
    while True:
        Frontiers = []
        new_bdd = fsm_bdd.post(loop_head).intersection(pre_reach_bdd)
        R = new_bdd
        while fsm_bdd.count_states(new_bdd) > 0:
            R = R.union(new_bdd)
            Frontiers.append(R)
            new_bdd = fsm_bdd.post(new_bdd).intersection(pre_reach_bdd)
            new_bdd = new_bdd.diff(R)
        R = R.intersection(recur_bdd)
        if loop_head.entailed(R):
            break
        else:
            loop_head = recur_states_list.pop(0)

\end{verbatim}
\end{scriptsize}
\noindent
Considering all the possible traces starting from the loop head, the layer at step \(i\) is 
the set of states that can be reached from the loop head in exactly \(i\) steps. 
The \texttt{Frontiers} list stores these layers. \\[2ex]
Once the loop head has been identified, the algorithm proceeds to reconstruct the loop body. 
The goal is to extract one specific trace through the system that starts at some earlier state,
progresses step by step, and eventually returns to the loop head, thereby forming a cycle.\\[2ex]
The algorithm first identifies the smallest index \(k\) such that the loop head appears in 
\texttt{Frontiers[k]}, meaning there is a path of length \(k\) from the loop head back to itself. 
This defines the loop length. Starting from the loop head, the algorithm then reconstructs the 
loop by moving backward layer by layer, selecting at each step a predecessor of the current
state that is in the correct frontier layer, while building the trace for visualization and the 
loop body. The actual code based on the pseudo-code presented during the course:
\begin{scriptsize}
\begin{verbatim}

    k = 0
    while not loop_head.entailed(Frontiers[k]):
        k += 1
    loop = [loop_head]
    trace = [loop_head.get_str_values()]
    curr = loop_head
    for i in range(k - 1, -1, -1):
        Pred = fsm_bdd.pre(curr).intersection(Frontiers[i])
        curr = fsm_bdd.pick_one_state(Pred)
        trace = [
            curr.get_str_values(),
            fsm_bdd.pick_one_inputs(
                fsm_bdd.get_inputs_between_states(curr, loop[0])
            ).get_str_values(),
        ] + trace
        loop = [curr] + loop

    trace = [
        loop_head.get_str_values(),
        fsm_bdd.pick_one_inputs(
            fsm_bdd.get_inputs_between_states(loop_head, loop[0])
        ).get_str_values(),
    ] + trace
    loop = [loop_head] + loop

\end{verbatim}
\end{scriptsize}
At this point of the computation the full loop has been indentified. The looping path is inside
the recurrent set, to finalize the witness the last step is to connect the loop body with one of
the initial state.\\[2ex]
The procedure backward searches for an initial state starting from the loop head and saving for 
each steps the pre-image of the states in the current \texttt{counterex}. The following code realizes 
this logic symbolically in Python using BDD operations:
\begin{scriptsize}
\begin{verbatim}

    images = list()
    counterex = pre_counterex = loop_head
    images.append(counterex)
    while not pre_counterex.intersected(fsm_bdd.init):
        counterex = pre_counterex
        pre_counterex = fsm_bdd.pre(counterex)
        images.insert(0, pre_counterex)

\end{verbatim}
\end{scriptsize}
The final step reconstructs the full counterexample starting from an initial state and 
leading to the loop head. The algorithm uses the layers computed during the backward 
search (i.e. \texttt{images}) to build a concrete trace.\\[2ex]
Beginning with the initial states, at each layer it selects a state that belongs both to the 
current layer (\texttt{images[i]}) and to the reachable set. Then, it applies the post operator to 
find successor states and intersects these with the next layer (\texttt{images[i+1]}) to ensure a 
valid transition.\\[2ex]
From this, one successor state and the input causing the transition are chosen and recorded. 
This process repeats until the loop head is reached, effectively creating a concrete prefix that 
connects the initial state to the start of the loop. Finally, the prefix 
trace constructed this way is concatenated with the previously built loop body into the final
output \texttt{witness}. The code below:
\begin{scriptsize}
\begin{verbatim}

    trace_init = list()
    start = fsm_bdd.init  # Start from initial states
    for i in range(0, len(images) - 1):
        start = start.intersection(images[i])
        post = fsm_bdd.post(start).intersection(images[i + 1])
        trace_init.append(fsm_bdd.pick_one_state(start).get_str_values())
        trace_init.append(
            fsm_bdd.pick_one_inputs(
                fsm_bdd.get_inputs_between_states(start, post)
            ).get_str_values()
        )
        start = post
    witness = trace_init + trace

\end{verbatim}
\end{scriptsize}
\noindent The final witness consists of a prefix from the initial state to the loop head,
followed by the loop that repeatedly violates the property, ensuring the trace satisfies 
\(\always\eventually f \AND \always\eventually \neg g\), thus falsifying the original implication.
